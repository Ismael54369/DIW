Paso de datos mediante GET y POST

Cuando un usuario rellena un formulario y pulsa el botón de enviar, los datos se transmiten a un servidor. Los métodos GET y POST son las dos formas principales de realizar este envío. La elección entre uno y otro depende del tipo de información y de la acción que se quiera realizar.

Método GET

El método GET envía los datos del formulario añadiéndolos directamente a la URL. Es como si enviaras una postal: el mensaje está a la vista de todos.

La URL resultante se ve así: pagina.php?nombre=Ismael&ciudad=Madrid

  • Ventajas:
    • Permite que la URL sea guardada en marcadores o compartida, ya que contiene todos los datos necesarios para "recrear" la página.
    • Es ideal para operaciones que no modifican datos, como búsquedas o filtros.
  • Desventajas:
    • Inseguro: Toda la información es visible en la barra de direcciones y en el historial del navegador. Nunca debe usarse para contraseñas o datos personales.
    • Limitado: Las URLs tienen una longitud máxima, por lo que no se puede enviar una gran cantidad de datos.

Método POST

El método POST envía los datos de forma "oculta" en el cuerpo de la solicitud HTTP. Es como enviar una carta dentro de un sobre cerrado: el contenido es privado.

La URL se mantiene limpia, sin mostrar los datos enviados: pagina.php

  • Ventajas:
    • Seguro: Es la forma correcta de enviar información sensible (contraseñas, datos bancarios, etc.), ya que los datos no son visibles.
    • Sin límite de tamaño: Permite enviar grandes volúmenes de información, incluyendo la subida de archivos.
  • Desventajas:
    • La página resultante no se puede guardar en marcadores.
    • Si el usuario recarga la página, el navegador mostrará una advertencia para confirmar el reenvío de los datos, lo que puede ser confuso.
